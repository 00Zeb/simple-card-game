The new ways

Agents doing TDD: it looks good, but it’s a charade

46%

of new tests passed at once: the agent already knew the answer

→ GLM did TDD by the book, and still ships “Josh wins 1 to 2”

→ Ten implementations, one design: a rank string, indexOf, two counters

→ On this kata, TDD didn’t change the agents’ design. It only tidied it.

46% is 26 of 57 tests, across the six agents told to do TDD by prompt. GLM by the book: 7 of 7 genuine reds, every commit labelled correctly. GLM returns “Josh wins 1 to 2” when Josh wins 2–1, and its own tests say that is correct: ask the room again what x was. Callback to Laforgia’s quote from the myths slide: by his definition (tests as a tool to design code), design the tests didn’t change isn’t TDD. The evidence: the run without TDD has the same design. The tidying is composed method: the TDD runs’ refactor steps split the code into small functions (Opus: return formatResult(scoreRounds(steve, josh))), while the no-TDD run is one function. Be fair: that is a point in TDD’s favour. No agent injected anything.
