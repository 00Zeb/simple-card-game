Forcing the smallest step

A perfect process as proof of quality

Red as the proof that a test can fail

→ Keep the proof, drop the ritual: mutation-test afterwards instead (Gorman, Böckeler)

For the agent, not for teaching humans: this is still how I teach people. Keep: the agreed examples and a check the agent didn’t write are the next slides. A failing test first for a bug is where red still carries information; that is outside this kata, but every agent agreed. Refactoring on green is what tidied the agents’ code. Leave behind: fake it guards against a human’s premature generalisation; the agent already knows the target, so it manufactures intermediate bugs. Beck’s own TDD allows bigger steps when you are confident (Obvious Implementation).
