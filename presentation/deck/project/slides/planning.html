Two lists that used to be one. The expectations (what must be true) are agreed with the team before the agent starts; Laforgia suggests writing them together, like a Specification by Example workshop. The test list (which unit tests, in what order) was the human’s working memory; it now belongs to the agent’s inner loop. Astra’s agreed plan also said “Read decks without modifying them”, but no test ever checked it: the gap that Expectation-Driven Development closes by making the agent prove each expectation. This talk as the example: we wrote and argued over the plan before generating any slides, and about 76% of the planned slides’ text (1,287 of 1,700 words) is still the first generated version. New requirements are left out: the three red/green/refactor slides imported from my old deck, the Expectation-Driven Development slide, the agenda and the references (with them included it is 60%).
